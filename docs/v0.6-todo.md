## Verification notes

- Verified package sources: `smtc_windows 1.1.0`, `tray_manager 0.5.3`,
  `window_manager 0.5.2` from pub.dev archives.
- `smtc_windows` exposes hardware/button events and native timeline update;
  the Dart wrapper archive does not expose a seek-request getter, so seek
  input remains an explicit integration risk rather than a fabricated API.
- Protected generated fixtures remain untracked and untouched.
- System seek capability is explicit: current adapter reports
  `supportsSystemSeekRequest == false`; see `docs/iterations/v0.6/smtc.md`.

## Frozen boundaries

`PlaybackRuntime` remains the sole owner of queue and playback state. Windows
ports only publish commands and render controller-provided snapshots. The
controller converts platform commands into `PlaybackClient.send` calls and
never writes playback state directly.
